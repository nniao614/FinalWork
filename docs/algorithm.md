# 算法实现规格（给编码 agent 的开发指南）

本文件规定**每个模块怎么实现、依据什么原理、按什么顺序开发、做到什么程度算完成**。
`docs/plan.md` 回答“做什么、为什么”，本文件回答“具体怎么写”。两者冲突时以 `plan.md` 的实验规则为准，并告知用户。

阅读顺序：`AGENTS.md` → `docs/plan.md` → 本文件。开发任何模块前，先读本文件对应的小节。

---

## 0. 总体原则（所有模块都要遵守）

1. **离线缓存、逐层解耦**。流水线是“小模型推理 → 构造路由单元 → 大模型复核 → 路由 → 合并 → 评估”。
   每一层的输出都写到磁盘缓存，下一层只读缓存。这样做的原因：
   - 路由网络和所有对照组要在**同一份**小模型输出、**同一份**大模型输出上比较，才公平；
   - 大模型推理很慢，跑一次要能反复用；
   - 调路由网络时不用重跑任何大模型。
2. **训练数据必须“没见过”**（out-of-fold，简称 OOF）。路由网络学的是“模型在新数据上会怎么错”。
   用模型在自己训练集上的输出当训练数据，错误几乎为零，标签全是假的。
   **小模型和大模型都适用这条规则**（见第 3.4 节）。
3. **验证集调参，测试集只跑一次**。任何阈值、温度、早停轮数、预算对应的阈值、外扩比例，都只能用验证集决定。
4. **所有方法共用同一套评估代码**：`src/eval/metrics.py`。新增指标往里加，不另起一套。
5. **先写单元测试再接真实数据**。测试用手工构造的小样本，不依赖数据集和 GPU（CI 里没有）。
6. **每个入口脚本**都用 `load_config` 读配置、`set_seed` 固定种子、`make_run_dir` 建输出目录、
   `get_device` 选设备。长任务在 Windows 上用 `scripts\run_bg.ps1` 后台启动。

## 1. 基本概念与数据结构

### 1.1 路由单元（FieldUnit）

**路由的最小单位是“一张票据的一种字段”**，即 `(sample_id, field)`。

- SROIE：每张票据固定 4 个单元（COMPANY / DATE / ADDRESS / TOTAL）。
- CORD：每张票据对 `fields_to_route` 中的每种字段各一个单元（见 1.3）。多值字段（如 `MENU.NM`）的值是列表，
  整个列表作为一个单元，正确的定义是：归一化后的多重集合与真实值完全相等（与 `field_prf` 里的 `exact_match` 口径一致）。
- **无论小模型是否预测出该字段，单元都存在**。小模型漏抽的字段也要能被路由（这是全局池化路径存在的原因）。
- 真实值和预测值都为空，算小模型正确。

放在 `src/router/units.py`：

```python
@dataclass
class FieldUnit:
    sample_id: str
    field: str
    pred_values: list[str]        # 小模型预测值（spans_to_fields 的结果），可能为空
    span_idxs: list[int]          # 小模型预测片段覆盖的所有词下标，可能为空
    gold_values: list[str]
    small_correct: bool
    vlm_values: list[str] | None  # 大模型复核结果（无定向提示版本）；解析失败为 None
    vlm_correct: bool | None
    is_simulated: bool = False    # 是否为模拟错误样本（第 6 节）
    sim_op: str | None = None

    @property
    def label_rescue(self) -> int:  # 本文训练目标：小模型错且大模型对
        return int((not self.small_correct) and bool(self.vlm_correct))

    @property
    def label_error(self) -> int:   # 对照组训练目标：小模型错
        return int(not self.small_correct)
```

单元正确性统一用一个函数判断，放在 `src/eval/metrics.py`：

```python
def values_match(field: str, pred: list[str], gold: list[str]) -> bool:
    """归一化后按多重集合比较；两边都为空也算正确。"""
```

### 1.2 缓存目录约定

所有缓存放在 `outputs/cache/`（不入库），路径里写清数据集、模型版本和划分：

```
outputs/cache/
  layoutlm/<dataset>/<run_tag>/<split>/<sample_id>.npz   # 每张票据一个文件
  layoutlm/<dataset>/<run_tag>/<split>/preds.jsonl        # 字段级预测汇总
  vlm/<dataset>/<model_tag>/<prompt_version>/<key>.json   # 大模型每次调用一个文件
  units/<dataset>/<tag>/<split>.jsonl                     # FieldUnit 列表
```

- `<split>` 取 `oof_train`（5 折交叉验证预测）、`validation`、`test`。
- `.npz` 内容：`hidden`（float16，形状 `[n_words, 768]`）、`logits`（float32，`[n_words, n_labels]`）、
  `fold`（整数，只有 `oof_train` 有）。**保存票据中所有词的向量**，不只是预测片段内的词。
- 大模型缓存的 `<key>` = 对 `(sample_id, 请求字段列表, 定向提示文本, 图像裁剪框, 模型与 LoRA 版本, prompt_version)`
  做 sha1。任何一项变了就是新调用，不会误用旧结果。JSON 里同时保存原始输出文本、解析结果、是否解析成功、耗时。

### 1.3 CORD 参与路由的字段

CORD 有 30 多种字段，很多很少出现。`configs` 里的 `router.fields_to_route` 默认为 `auto`：
取训练集中**出现在至少 50 张票据里**的字段。其余字段直接用小模型的结果（照常参与 F1 评估）。
实际字段名以 `labels.json` 为准，常见的有 `MENU.NM / MENU.CNT / MENU.PRICE / SUB_TOTAL.SUBTOTAL_PRICE /
SUB_TOTAL.TAX_PRICE / SUB_TOTAL.SERVICE_PRICE / SUB_TOTAL.DISCOUNT_PRICE / TOTAL.TOTAL_PRICE / TOTAL.CASHPRICE /
TOTAL.CHANGEPRICE`。最终选出的字段列表写进运行目录，论文里要列出来。

## 2. 小模型：LayoutLMv3（`src/layoutlm/`）

### 2.1 原理

LayoutLMv3 同时输入文字、文字框坐标和图像块，用 Transformer 联合建模，输出每个子词的表示。
本项目把它当**词级序列标注**模型用：每个词预测一个 BIO 标签，再把连续的同类标签拼成字段值。

### 2.2 输入构造（`dataset.py`）

- 用 `LayoutLMv3Processor`，设 `apply_ocr=False`，直接传入 `Sample.words` 和 `Sample.normalized_boxes()`。
- 一个词会被切成多个子词。**只有第一个子词带标签**，其余子词标签设为 `-100`（不计损失）。
  后续所有“词级”量（logits、隐藏层向量）都取**第一个子词**的值。
- **超过 512 个子词的票据要切窗口**（SROIE 有不少长票据）：用 tokenizer 的 `return_overflowing_tokens=True`、
  `stride=128`，每个窗口配同一张图。推理时一个词可能出现在多个窗口，取该词**离窗口边缘最远**的那个窗口的结果
  （边缘处上下文不完整）。写单元测试覆盖“窗口合并后每个词恰好有一个结果”。

### 2.3 训练（`train.py`）

- 标准 token 分类交叉熵，AdamW，lr 5e-5，线性预热 10%，bf16（Windows）。超参数见 `configs/base.yaml` 的 `layoutlm` 段。
- **完整模型**：在全部训练集上训练，用验证集字段级 F1（`field_prf` 的 micro F1）做早停，记录最佳轮数 `E*`。
- 输出：最佳权重、每轮验证 F1 曲线、`E*`。

### 2.4 5 折交叉验证预测（`cv.py`）

目的：得到小模型在“没见过的票据”上的预测，作为路由网络的训练数据。

1. 训练集按 `sample_id` 排序，用种子 42 打乱，均分为 5 折。折号写进缓存。
2. 第 k 折：用其余 4 折训练，**固定训练 `E*` 轮，不再看验证集**（省时间，也避免交叉验证模型间接接触验证集），
   然后在第 k 折上推理。
3. 5 折合起来就是 `oof_train`。验证集和测试集用**完整模型**推理。

注意：交叉验证模型只用了 80% 的训练数据，比完整模型略弱，错误分布会略有不同。论文里说明这一点即可，属于标准做法。

### 2.5 推理与缓存（`infer.py`）

对每张票据保存：
- 所有词的最后一层隐藏层向量（第一个子词，float16）和 logits；
- 用 `decode_bio` + `spans_to_fields` 得到的字段值和片段词下标，写入 `preds.jsonl`。

验收：在 SROIE 验证集上，`只用小模型` 的 micro F1 达到常见报告水平（约 0.9 以上，具体以跑出来为准）；
`oof_train` 的 F1 应**低于**完整模型在训练集上的 F1（否则说明交叉验证写错了）。

## 3. 大模型：Qwen2.5-VL（`src/vlm/`）

### 3.1 原理

视觉语言模型直接看整张票据图像，按提示生成字段值。它不依赖 OCR 的切词和标注边界，
因此能修正小模型的**边界错误、误抽、漏抽**，有时还能修正 OCR 识别错误；代价是慢。

### 3.2 提示与输出格式（`prompts.py`、`parse.py`）

- 一次调用对应**一张票据**，提示中列出本次需要复核的字段（可以是 1 个，也可以是全部）。
- **独立抽取**：提示中**不包含小模型的预测值**。原因：这样大模型的回答不依赖小模型，
  缓存的结果可以复用于任何小模型输出（包括第 6 节的模拟错误样本）。
- 定向提示（第 5 节）只描述“哪里不一致”，例如“小计、税、服务费之和与总额不符”，不给出具体数值答案。
- 输出要求为 JSON：`{"FIELD": "值"}`，多值字段为列表，不存在为 `null`。字段名用数据集里的大写名称，
  在提示中对每个字段附一句英文或中文含义说明（写在 `prompts.py` 的字典里）。
- 解析：先找第一个 `{` 到最后一个 `}`，`json.loads`；失败则尝试修复常见问题（单引号、结尾多余逗号）；
  仍失败则该次调用标记为解析失败，相关字段**回退到小模型结果**，并计入解析失败率。
- 提示模板有版本号 `prompt_version`，改模板就改版本号（缓存因此自动失效）。

**假设与验证**：同一个字段在“只问这一个字段”和“问全部字段”时的回答被视为相同（路由标签是用“问全部字段”生成的）。
需要在验证集上随机抽 100 张票据，比较两种问法的逐字段准确率并报告；差异明显时告知用户。

### 3.3 LoRA 微调（`sft.py`）

- 训练样本：图像 + “抽取全部路由字段”的提示 → 目标为真实字段值的 JSON。损失只算回答部分的 token。
- 配置：LoRA r=16、alpha=32，作用于注意力的 q/k/v/o 投影；bf16；开梯度检查点；batch 1、梯度累积 8；
  用 `max_pixels` 控制图像分辨率，保证 16G 显存放得下（票据是细长图，先试 `1024*28*28`）。
- 解码：贪心（temperature=0），`max_new_tokens` 见配置。
- 用 `transformers` + `peft` + `qwen-vl-utils`，设备用 `get_device()`。

### 3.4 大模型也要交叉验证（重要）

如果 LoRA 用全部训练集微调，再在训练集上生成路由标签，大模型等于“见过答案”，
“大模型对”的比例会被高估，路由网络学到的修正收益偏乐观。因此：

- **生成 `oof_train` 的标签**：训练集按种子 42 分成 **2 折**（与小模型的 5 折独立），
  每折用另一折微调 LoRA，在本折上推理。2 折是成本和偏差的折中，论文里说明。
- **验证集、测试集**：用全部训练集微调的 LoRA。
- 零样本版本（消融“大模型不做 LoRA”）没有这个问题，直接推理即可。
- 时间不够时的退路：只用零样本模型生成标签和做复核，把 LoRA 作为单独的“只用大模型”对照。此时要告知用户。

### 3.5 复核接口（`review.py`）

```python
def review(sample: Sample, fields: list[str], hints: dict[str, str] | None = None,
           crop: tuple[int, int, int, int] | None = None) -> ReviewResult:
    """对一张票据的若干字段做独立抽取。先查缓存，命中则直接返回（同时返回缓存里记录的原始耗时）。
    crop 为图像裁剪框（扩展二：区域聚焦复核用），默认 None 表示整图。"""
```

- 生成路由标签时：对 `oof_train`、`validation`、`test` 的每张票据，请求**全部路由字段、不带定向提示**，结果全部缓存。
  这一份同时就是“只用大模型”对照组的结果。
- 在线评估（计时实验）时：一张票据只调用一次，请求所有被选中的字段，带上这些字段的定向提示。

## 4. 路由网络（`src/router/model.py`）——主创新

### 4.1 原理

小模型的 softmax 置信度过于自信，用它挑字段效果有限。另外，“小模型错”不等于“值得送大模型”：
有些字段两个模型都做不对，送过去只是浪费调用。路由网络直接学习**送大模型后能被改对的概率**（修正收益），
利用的信息比单个置信度丰富得多：小模型内部的隐藏层表示、完整的标签概率分布、版面位置、跨字段一致性。

### 4.2 每个词的输入向量

对票据中第 i 个词、当前字段 f：

```
x_i = concat( W_h · h_i ,          # 隐藏层向量 768 → d（d=256），线性投影
              p_i ,                # 该词完整的标签概率分布（n_labels 维，softmax(logits)）
              b_i )                # 归一化框坐标（x0,y0,x1,y1)/1000，4 维
u_i = LayerNorm(W_x · x_i)         # → d 维
```

`p_i` 用的是完整分布而不是最大概率（借鉴 VST/PRTR 用概率向量代替 argmax 的做法），能体现“模型在哪几个类别之间犹豫”。

### 4.3 双路径池化

**片段路径**（小模型预测片段内的词，集合 S_f）：

```
a_i = v_f^T · tanh(W_a · u_i),  i ∈ S_f        # v_f：每种字段一个可学习向量
α   = softmax(a)（只在 S_f 内归一化）
s_f = Σ α_i · u_i
S_f 为空（漏抽）时：s_f = 0，并置特征 empty=1
```

**全局路径**（整张票据所有词，借鉴导师工作 VST 的 VS-Align：`S = softmax(QVᵀ)V`）：

```
β   = softmax( q_f^T · (W_k · u_i) / sqrt(d) ),  i = 1..n    # q_f：每种字段一个可学习查询
g_f = Σ β_i · (W_v · u_i)
```

全局路径的作用：小模型漏抽或抽错位置时，它能注意到票据上**其他像该字段的位置**（因为 u_i 里含有该词属于字段 f 的概率）。

**门控融合**（借鉴 PRTR 的 DPSA）：

```
G   = sigmoid( W_g · [s_f ; g_f] )        # d 维门
z_f = G ⊙ s_f + (1 − G) ⊙ g_f
```

配置项 `router.pool`：`span` / `global` / `dual`（默认）；`router.fusion`：`gate`（默认）/ `concat`，用于消融。

### 4.4 单元级标量特征（`units.py` 中计算）

| 特征 | 说明 |
|---|---|
| conf_min, conf_mean | 片段内各词所预测标签概率的最小值、平均值；漏抽时取 1 − 全文各词属于 f 的最大概率 |
| entropy_mean, entropy_max | 片段内各词标签分布的熵 |
| margin | 片段内各词“第一与第二大概率之差”的最小值 |
| n_spans, span_len | 预测片段数、词数（单值字段出现多个片段本身就是异常信号） |
| empty | 是否漏抽 |
| pos_x, pos_y | 片段中心的归一化坐标 |
| consistency | 第 5 节的一致性特征，固定长度向量 |
| field_emb | 字段类型嵌入，16 维（可学习） |

标量特征先用训练集统计量做标准化（均值方差保存到运行目录，推理时复用）。

### 4.5 输出与损失

```
logit = MLP( [z_f ; 标量特征 ; field_emb] )      # 两层，隐藏 256，ReLU，dropout 0.1
p_rescue = sigmoid(logit)
```

- 损失：焦点损失（γ=2，α 在验证集上从 {0.25, 0.5, 0.75} 中选），或类别加权 BCE（`router.loss`）。
- 训练目标由 `router.target` 决定：`rescue`（本文）或 `error`（对照组，同一网络换标签）。
- 训练数据：`oof_train` 的真实单元 + 模拟错误单元（第 6 节）。早停和超参数选择用 `validation` 的真实单元，
  选择指标为**正类的 PR 曲线下面积（AUPRC）**，因为正样本稀少，准确率没有意义。
- 小数据集上训练很快（CPU 都能跑），固定种子，有时间再报多种子均值。

### 4.6 推理：从分数到路由决策

- **预算模式**（画核心曲线用）：对测试集所有单元按分数降序，取前 B% 送大模型，B 扫描 0、5、10、…、100。
  这是离线评估，用于比较“同样调用量下谁改对得多”。
- **阈值模式**（计时实验用）：在验证集上找到使调用比例约等于目标预算的阈值，测试时逐张票据按阈值决策。
  报告测试集上的实际调用比例。

### 4.7 合并规则（`pipeline.py`）

- 未被选中的单元：用小模型结果。
- 被选中且大模型输出解析成功：用大模型结果（包括大模型认为字段不存在、返回 null 的情况）。
- 被选中但解析失败：用小模型结果，计入解析失败率。
- 扩展三（OCR 约束）开启时：大模型值的每个词在 OCR 词中找不到近似匹配（归一化编辑距离 > 阈值）则回退到小模型。
  默认关闭。

## 5. 跨字段一致性约束（`src/router/consistency.py`）

### 5.1 金额解析

写 `parse_amount(text) -> float | None`，必须处理：
- 货币符号和字母（`RM 9.00`、`Rp. 60.000`）；
- **印尼格式千分位**：CORD 中 `60.000` 表示六万，不是 60.0。规则：匹配 `^\d{1,3}([.,]\d{3})+$` 时把分隔符都当千分位；
  否则把最后一个 `.` 或 `,` 后面跟 1～2 位数字的情况当小数点。
- 解析失败返回 None。写充分的单元测试。

注意 `metrics.canonicalize` 只用于字符串比较，算术校验不要用它。

### 5.2 规则

| 编号 | 数据集 | 规则 | 涉及字段 |
|---|---|---|---|
| R1 | CORD | 小计 + 税 + 服务费 − 折扣 ≈ 总额 | SUB_TOTAL.*、TOTAL.TOTAL_PRICE |
| R2 | CORD | Σ 菜品金额 ≈ 小计（无小计时与总额比） | MENU.PRICE、SUB_TOTAL.SUBTOTAL_PRICE |
| R3 | CORD | 现金 − 总额 ≈ 找零 | TOTAL.CASHPRICE、TOTAL.TOTAL_PRICE、TOTAL.CHANGEPRICE |
| F1 | 两者 | 金额字段可解析为数字 | 所有金额类字段 |
| F2 | SROIE | 日期可解析（多种格式，含年份合理性） | DATE |

- 约等于：`|左 − 右| ≤ max(tol × |右|, 0.01)`，`tol` 取配置 `router.consistency.amount_tolerance`。
- 规则中某个字段缺失时：该规则记为“无法校验”，不算违反。
- 规则所用的值来自**当前**小模型预测（模拟错误样本用扰动后的值重新计算）。

### 5.3 输出

对每个单元输出固定长度向量：`[参与的规则数, 违反的规则数, 最大相对残差（截断到 [0, 1]）, 格式是否合法]`；
同时为违反规则的字段生成定向提示文本（中英文均可，写在 `prompts.py`，带版本号）。

## 6. 特征层面的模拟错误（`src/router/simulate.py`）

### 6.1 原理

借鉴导师工作 PRTR 的在线概率增强（OPA）：纠错模型缺少可学的错误样本时，就人为制造“看起来像模型会犯的错误”。
本项目中小模型准确率高，“小模型错且大模型对”的正样本很少，用这种方法扩充训练数据。

### 6.2 操作

只对 `oof_train` 中**小模型正确且预测非空**的单元做扰动，每个单元随机选一种操作：

| 操作 | 做法 | 模拟的错误类型 |
|---|---|---|
| shrink | 去掉片段的第一个或最后一个词（片段至少 2 个词） | 边界错误（少词） |
| expand | 按阅读顺序把相邻的一个词加进片段 | 边界错误（多词） |
| swap | 片段换成另一组词：优先取全文中属于 f 的概率最高、但不在原片段内的连续词 | 误抽 |
| drop | 片段置空 | 漏抽 |
| mix | 片段内某个词的概率向量与“概率向量记忆库”中随机一个混合，λ ~ U(0.3, 0.7) | 置信度扰动（照搬 OPA 的 mixture） |

- 扰动后用缓存的 hidden 和 logits **重新计算全部特征**（包括一致性特征），不需要重跑小模型。
- 重新计算预测值后与真实值比较：如果碰巧仍然正确，丢弃这个样本。
- `mix` 只改变概率特征、不改变预测值，所以预测仍正确，**它产生的是负样本**，作用是让网络不要只靠置信度判断。
- 标签：模拟单元的小模型一定错；大模型是否正确直接用缓存的**无定向提示**复核结果。这依赖第 3.2 节的独立抽取。
- 数量：模拟单元数 = `router.simulate.ratio` × 真实正样本数，默认 1.0，在验证集上选。
- **只用于训练**，验证集和测试集绝不加入模拟单元。

## 7. 对照组（`src/router/baselines.py`）

所有对照组都输出“每个单元的分数”，然后走与本文方法相同的预算模式、阈值模式和合并规则，保证可比。

| 名称 | 分数 |
|---|---|
| random | 固定种子的随机数 |
| confidence | 1 − conf_min（越不自信越优先） |
| confidence_calibrated | 同上，但 logits 先做温度缩放：在验证集上拟合单个温度 T，最小化词级 NLL |
| whole_doc | 票据级：一张票据里任一单元 confidence 超过阈值，则该票据**所有**路由字段都送大模型 |
| error_net | 路由网络，`target=error` |
| oracle（参考线） | 分数 = label_rescue，表示理论上限，只用于画图，不算对照组 |

## 8. 评估（`src/eval/`）

### 8.1 补充指标（加到 `metrics.py`）

```python
def routing_outcomes(units, routed: set, final_values) -> dict:
    """返回调用比例、改对数（小模型错→最终对）、改错数（小模型对→最终错）、净收益、
    改对率 = 改对数 / 被送去的单元数、改错率。"""
```

### 8.2 错误类型（`error_types.py`）

用小模型片段词下标与真实标签片段词下标比较，对每个小模型出错的单元按优先级分类：

1. `missing`：预测为空，真实非空；
2. `spurious`：预测非空，真实为空；
3. `wrong_entity`：预测片段与真实片段没有任何重叠；
4. `boundary`：有重叠但词集合不同；
5. `char`：词集合相同但值不一致（OCR 文本与真实值不符，SROIE 常见）。

多值字段：只要有一个值属于某类就按上述优先级取最高的一类。输出每类的占比、各路由方法在同一预算下的选中率、大模型改对率。
真实片段从 `Sample.labels` 的 BIO 解码得到；SROIE 中匹配失败（没有词级标签）的字段单独归为 `unlabeled`，不参与分类。

### 8.3 计时（`timing.py`）

- 计时范围：读图 → 预处理 → 小模型 → 构造特征 → 路由 → （若有选中字段）大模型复核 → 合并。
- 同一张卡，batch=1，先预热 10 张不计入；GPU 计时前后调用 `torch.cuda.synchronize()`。
- 计时实验中**大模型必须真实调用**，不能读缓存（缓存只用于离线的准确率评估）。
- 记录：平均耗时、P95 耗时、吞吐量、`torch.cuda.max_memory_allocated()` 峰值。

### 8.4 核心图

横轴为大模型调用比例（另画一张横轴为平均耗时），纵轴为测试集 micro F1。
每种路由方法在不同预算下连成一条曲线，两个单模型各画一个点，oracle 画虚线。

## 9. 拍照场景增强与鲁棒性（`src/augment/`，第 11～13 周）

- `photo.py`：用 albumentations 实现模糊（运动/高斯）、阴影、褶皱（网格或弹性变形）、透视变形，每种分 3 档强度。
  训练用增强时，框坐标要随几何变换一起变换。
- `reocr.py`：增强后的图像用 PaddleOCR **重新识别**，得到新的词和框；再用与 `src/data/sroie.py` 相同的匹配规则，
  把字段真实值匹配到新的词上，生成新的 `Sample`。CORD 同理。匹配率要统计并报告。
- 端到端鲁棒性测试集按“增强类型 × 强度”分组报告 F1 和调用比例。
- 增强得到的难样本可以进入路由训练集（与第 6 节的特征层面模拟互补），但同样只用于训练。

## 12. 常见陷阱（写代码前看一遍）

- 用完整小模型在训练集上的预测训练路由网络 → 错误。必须用 `oof_train`。
- LoRA 用全部训练集训练后在训练集上生成标签 → 错误。必须用 2 折（3.4）。
- 在测试集上选阈值、温度、预算阈值 → 错误。
- 复核提示里放小模型的预测值 → 违反独立抽取，模拟错误样本的标签失效。
- 只保存预测片段内的词向量 → 全局路径和模拟错误都无法实现。
- 计时实验读大模型缓存 → 耗时失真。
- 用 `canonicalize` 做金额算术 → CORD 的 `60.000` 会被当成 60。
- 代码里写死 `"cuda"`、用字符串拼路径、在 Windows 前台跑长任务 → 违反 `AGENTS.md` 的环境约定。
